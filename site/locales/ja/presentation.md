# 旅行スライドの制作資料

下の旅程データをもとに、依頼された場合にだけスライドを制作します。
実行環境のスライド作成ツールで、指定されたファイルを作成して表示を確認してください。この資料はMarkdown形式です。

## 制作前に構成を決める

合意した旅行条件を旅程データが満たすか確認します。計画も依頼されている場合は、不足する重要情報を調査に戻します。形式の変更だけが目的なら、不明な点を残して明示します。
各ページを実際の訪問先、日付、選択肢と結び付けます。料理のページでは店名だけでなく、郷土料理そのものも紹介します。写真を探す前に必要な内容を整理します。

日付と宿泊する街から概要を組み立て、その後に街ごとの宿、観光、食事を紹介します。
テーマ別のページにも日付や一日の流れを添え、旅程との関係が分かるようにします。内容に合わせてページ数と構成を選びます。

参考スライドがある場合は、最新の関連ページで写真と文字のバランス、ページの展開を確認します。
利用者の旅程や素材は作業領域で管理し、指定のデザインを優先します。

| ページ | 構成と掲載情報 |
| --- | --- |
| 表紙・概要 | タイトル、日付、訪問する街の順番と泊数を、読みやすい地図または現地写真と一緒に表示します。`revision`、注意事項、デモの表示も残します。 |
| 宿泊 | 施設名、宿泊日、アクセス、客室・食事・設備の情報。適切な素材があれば、大きな客室写真と小さな共用部写真を組み合わせます。施設や客室タイプを明記し、部屋の割り当ては予約条件で確認します。 |
| 観光 | 大きな写真と短い解説、または関連する二つの場所を写真と説明で紹介します。見どころと、旅程に入れた理由を書きます。複数のエリアを比較するときは三〜四枚の写真も使えます。 |
| 食事 | 郷土料理の写真と説明を置き、飲食店の候補と違いを添えます。選択済みの店なら、店内と代表料理の写真で利用イメージを伝えます。時間帯、コース、人数条件を残します。 |
| 特別な体験 | 大きな写真と小さな情報欄で、催し、日付、時間、利用条件を紹介します。過去の季節や夜間の写真は参考として明記します。 |
| 交通・確認事項 | 編集できる概略図や表で、出発地・到着地、日付、手段、時刻、乗り換え、未確認事項を示します。 |

デザイン指定がなければ、温かみのある紙色、深緑、テラコッタを使います。現地写真に十分な面積を取り、説明を短くまとめます。
見出しと実用情報は編集できるようにし、情報量が多ければページを分けます。地図は位置と移動を説明する用途で使い、概略図にはその旨を明記します。

## 写真の選定と出典

訪問先、施設、料理が正しく写った写真を探し、再利用の許諾を確認します。施設や観光機関の公式素材に適切な利用許諾があれば優先します。
第三者の写真は現地の紹介に使えます。アクセス、営業時間、空室などの判断は、それぞれの情報源で確認します。

素材ID、対応する地点・都市、被写体、出典ページ、作者、ライセンス、分かる範囲の撮影時期、掲載ページ、説明の範囲を一覧にします。
ローカルパスは非公開の作業領域で管理し、スライドには短いクレジットとリンクを付けます。詳しい出典、許諾、トリミングや変更の記録はノートやクレジット欄へ。
許諾や素材の一致を確認できないときは、出典へのリンク、文章、地図で伝えます。

調べた候補と選択済みの宿・飲食店を区別します。エリア写真や料理のイメージは用途を明記します。
写真の出典と制作上の注記はJSONに添えて管理します。旅行情報や選択肢を変更した場合は、まず共有データを更新します。
第三者素材や非公開の参考スライドは、リポジトリと配布物の外に保管します。

## 共通データと仕上がりの確認

名称、日付、宿泊する街、訪問先、交通は旅程データから取得します。旅程上の役割と確認状況を分けます。
`sources.scope` に従って記述し、座標の出典は位置の確認に使います。候補と代替案は区別したままにします。
運賃、営業条件、空き状況が分からない場合は未確認と表示し、新しい候補は先に共有データへ追加します。

日ごとの予定と移動をHTML・JSONと照合します。表示したスライドで、観光地、宿、食事が伝わるか、写真の内容と裁ち方、文字の収まり、リンクを確認します。
写真は納品ファイルに埋め込みます。書き出したファイルで文字が表示されることと、明暗の背景でリンクが読みやすいことを確認します。
重要な利用条件は該当する場所に添え、ノートやメタデータから個人のパス、アカウント、端末情報を除きます。
制作物と検証記録はリポジトリの外に保管します。非公開の旅程を公開・共有する場合は、利用者の依頼範囲を確認します。
