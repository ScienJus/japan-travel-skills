# 旅行演示文稿制作提纲

下方的完整行程记录用于提供数据。只有在用户要求演示文稿时才读取此提纲。
使用宿主的幻灯片制作工具生成并渲染所需文件。此提纲为 Markdown。

## 制作前先编排内容

先核对行程是否能支撑用户确认的需求。若任务包含规划，先回到规划环节补齐会影响旅行决策的信息；若只调整格式，保留并说明原有缺口。
让每页主题关联具体的日期、地点和选择，并标明只靠占位内容支撑的部分。地方美食页应介绍菜品，而不仅仅列出餐厅。确定实用内容之后，再寻找适合的图片。

制作一份能用于旅行的图文指南。按日期和住宿城市组织概览，再按城市展开住宿、景点与美食。
在主题页保留日期或简短的当天动线，以便与行程对应。根据内容选择页数与版式。

若用户提供了参考演示文稿，先检查最新的相关页面，理解图文比例和节奏。
将私人行程、图片和本地文件位置留在用户的工作区。用户指定的设计优先。

| 页面 | 布局与信息 |
| --- | --- |
| 开场 | 标题、日期、城市顺序和住宿晚数，配清晰的路线概览或目的地实景图。保留 `revision`、重要提示与样例标识。 |
| 住宿 | 酒店名、住宿日期、交通和相关房型、餐饮或设施信息。适合时搭配一张大幅客房图及一张较小的公区图。标明图片对应的房型或设施，房间分配仍以预订为准。 |
| 景点 | 一张大图加简短说明，或两处相关景点各配一图一说明。写清看点和安排理由。需要比较片区时，可以使用三至四张图片的概览。 |
| 美食 | 用可辨识的菜品照片和简短介绍说明地方美食，再列出餐厅候选及其差异。已选餐厅可搭配店内照片与该店代表菜，保留餐次、套餐和人数条件。 |
| 特别体验 | 用大图搭配窄栏，写明活动、日期、时间和关键条件。历史季节或夜景照片仅用于说明可能的体验。 |
| 交通与待决事项 | 用可编辑的示意图、表格或清晰排版保留起终点、日期、交通方式、时间、换乘和待确认事项。 |

用户未指定风格时，可用暖纸色、深绿和陶土色。目的地页面给照片留出空间，使用简单图注、统一边距和短段落。
标题与实用信息应可编辑。信息过密时拆页。地图用于解释位置和移动，示意线标明范围。

## 图片选择与出处

优先寻找能准确对应景点、酒店或菜品且有适当再使用许可的图片。优先考虑设施或观光机构授权素材。
获许可的第三方照片可以介绍地点。营业、交通、房态及未来情况仍应使用相应的来源核对。

随产物保留简短图片清单，记录图片编号、关联的地点或城市、主题、来源页面、作者、授权、已知拍摄日期或季节、使用页及说明范围。
本地路径只在私人工作区记录。页面保留简短署名和链接，完整授权、裁切和修改说明放在备注或可访问的署名页。
找不到许可明确且匹配的图片时，使用来源链接、文字或地图。

区分考察中的候选与已选酒店或餐厅。区域照片是区域参考，菜品示意应明确标注。
图片出处和排版说明可以随 JSON 保存。新增事实或变更选择时，先更新共享行程，再更新受影响的交付。
第三方素材和私人参考演示文稿放在仓库和发布包之外。

## 共享数据与验收

名称、日期、住宿城市、地点和交通均从下方记录取得。分开保留行程角色与证据状态。
`sources.scope` 决定一条来源能证明什么，坐标来源只支持位置相关的核查。候选与备选应继续标注。
票价、开放条件和库存仍未知时，按待确认展示。新增的研究候选先写入共享行程，是否采用由用户另行决定。

逐日对照 HTML 和 JSON。渲染后检查目的地、住宿、美食是否清楚，图片是否匹配，裁切、文字、排版和链接是否正常。
照片应嵌入交付文件。实际检查导出后的字体与明暗背景下的链接对比度。把会影响决策的条件放在对应信息旁边。
检查导出文件的备注和元数据，清理私人路径、账号和设备信息。交付与验收记录存放在仓库之外，公开私人行程前先确认用户的分享意图。
